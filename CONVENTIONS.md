

- Při `Nullable=disable` neinicializuj referenční vlastnosti jen kvůli nullability, např. nepoužívej `= string.Empty` ani `= null!`. Inicializace kolekcí potřebné pro jejich použití a skutečné provozní výchozí hodnoty zůstávají.

- AuthService nezná DbContext ani EF API a neskládá LINQ databázové dotazy. Používá metody IUserRepository; obsazenost e-mailu včetně smazaných účtů kontroluje UserExistsByEmailAsync. Dotaz a IgnoreQueryFilters patří do implementace repozitáře.
- Repozitáře pouze načítají entity a připravují změny; nemají Commit ani SaveChanges. IUnitOfWork v Base vystavuje SaveChangesAsync, BeginTransactionAsync, CommitTransactionAsync a RollbackTransactionAsync. Implementace v Data drží transakci uvnitř, CommitTransactionAsync uloží změny a potvrdí transakci; rollback odpojí sledované entity, aby se změny po vrácení transakce později neuložily. Ve službách nepoužívej try/catch pro řízení transakcí. AuthService při očekávaném neúspěchu volá rollback před vrácením výsledku; při výjimce vrátí nepotvrzenou transakci UnitOfWork.DisposeAsync při ukončení DI scope. Scoped DI uvolňuje UnitOfWork, které při dispose vrátí případnou nepotvrzenou transakci; sdílený DbContext vlastní a uvolňuje DI. Identity, OpenIddict, repozitáře a UnitOfWork sdílejí jednu scoped instanci kontextu. Identity a OpenIddict si interně ukládají své operace, společnou transakci řídí UnitOfWork. Obal RepositoryTransaction se nepoužívá.
- Nullable ID uživatele při kontrolách načítej do proměnné a ověřuj přes HasValue, nepoužívej vazebný pattern is not { } v podmínce nebo ternárním výrazu. Vnořené asynchronní získání hodnoty pro parametr rozděl do proměnné a následného volání.

- DateTime a DateTime? na našich entitách implementujících IBaseEntity mapuje společná DateTimeConvention na timestamp without time zone. Konvence je registrovaná přes ConfigureConventions; mapování časů knihovních entit Identity a OpenIddict nemění.

- OpenIddict používá klíče z AuthOptions místo certifikátů: SigningPrivateKey je PEM RSA privátní klíč (alespoň 2048 bitů), EncryptionKey je Base64 kódovaných 32 náhodných bajtů. appsettings.Development.json obsahuje pouze veřejné vývojové klíče; pro produkci nastav vlastní stabilní klíče přes secrets nebo prostředí. Klíče se při každém startu negenerují a všechny instance musí používat shodné klíče. Změna klíčů bez zachování starých zneplatní již vydané tokeny.

- Články: ArticleEntity dědí ExtendedBaseEntity<int>, ArticleType je enum v Core (Police=1, Firefighters=2, Army=3) a v DB se ukládá jako string. Veřejné GET endpointy /api/v1/articles a /api/v1/articles/{id}. Seznam přijímá FilteredRequest<ArticleFilter> s PageNumber, PageSize, SortBy a SortDirection. ArticleFilter obsahuje pouze Type a SearchValue, obě properties jsou string. SearchValue hledá podřetězec v Title OR Content bez rozlišení velikosti písmen přes ToLower().Contains(); nejde o sémantické ani PostgreSQL full-text hledání. Soft delete respektuje globální filtr. Pro starší DB zůstává připraven skript PublicSafetyHub.Data/Scripts/001_CreateArticles.sql; EnsureCreated existující schéma neaktualizuje.

- Společný request je PaginationRequest (PageNumber=1, PageSize=20, SortBy, SortDirection=asc) a FilteredRequest<TFilter> s volitelným Filter. FilteredRequest se ve službě nevaliduje přes FluentValidation; PaginationRequestValidator se nepoužívá. Technické meze stránky a velikosti hlídá ApplyPagination; Typ článku se samostatně nevaliduje. Chybějící, prázdný nebo neznámý SortBy znamená řazení podle Id bez validační chyby. PagedResult vrací pouze Items, TotalCount, PageNumber, PageSize. Offset/Size a SortPropertyName/SortDescending už API nepoužívá.
- Používej Query Specification pattern s explicitním, typově bezpečným mapováním filtru na entity a operátory. Filtr se přes AutoMapper přemapuje na properties konkrétní specifikace. Její GetCriteria() pomocí běžných if přidává aktivní Expression<Func<TEntity,bool>> podmínky do seznamu a nakonec seznam vrátí; nepoužívej yield return. Jde o jednoduchou variantu inspirovanou WorkContract API a veřejnými příklady Ardalis, nikoli jejich kopii. Společný základ Specification řeší řazení a stránkování přes ApplyPagination. Tuto metodu volá centrálně BaseRepository.GetPagedAsync; služby předají specifikaci a FilteredRequest, neopakují volání ApplyPagination. Null nullable skaláru nepřidá podmínku, 0 a false jsou aktivní filtry. Null, prázdný string a whitespace nefiltrují; null a prázdná kolekce také nefiltrují. Podmínky se skládají AND; u článků text hledá Title OR Content. Filtry ID, kolekcí, dat ani HasUpdates články nemají. Shoda názvů properties nesmí automaticky určovat filtr. AutoMapper přenáší pouze hodnoty filtru; jejich význam a operátory určuje explicitní GetCriteria(). Nepřidávej reflexní odhadování podmínek, generickou mapovací factory ani třídy specifikací pro jednotlivé properties.
- Repozitáře používají zděděné GetAsync pro ID. GetPagedAsync přijímá specifikaci, PaginationRequest a volitelný CancellationToken, vrací stránku entit bez projekčního overloadu; stránkování i řazení uchovává specifikace. Společný SpecificationEvaluator přidává Where, OrderBy/ThenBy a teprve potom Skip/Take. Pro TotalCount se spouští criteriaOnly=true bez stránkování a řazení. Nepoužívaná podpora Includes a třída SpecificationOrder jsou odstraněné; pro řazení stačí OrderBy, SortDescending a ThenBy. BaseRepository používá AsNoTracking pro čtení a CountAsync i ToListAsync volá postupně se stejným CancellationToken. Repository načte stránku entit a služba následně převede PagedResult<TEntity> přes mapper.Map na PagedResult<TModel>. Filtry, řazení a stránkování zůstávají v SQL. V DB dotazu se nesmí používat Compile, IsSatisfiedBy, předčasné ToList nebo AsEnumerable. Jedna konkrétní specifikace řeší celý seznam, nevytvářej specifikaci pro každou property.
- Model entity se jmenuje stejně jako entita bez přípony Entity (ArticleEntity -> Article, UserEntity -> User), pokud uživatel neurčí jinak. Pojmenování explicitních requestů typu RegisterUserRequest zůstává. Pro mapování používej AutoMapper 14.0.0 s profily v Application/Mappings a registrací v Host/BuilderExtensions. Jde o verzi před zavedením licencování ve verzi 15; NuGet aktuálně hlásí NU1903 pro tuto verzi, upozornění nepotlačuj. Mapy používej bez MaxDepth a bez explicitního MemberList.Source, pokud uživatel neurčí jinak.

- Zdroj pro Query Specification + Repository: https://specification.ardalis.com/related-resources/patterns-used.html a podmíněné přidávání Where https://specification.ardalis.com/features/where.html. Query by Example přes reflexi bylo nahrazeno explicitní specifikací dle nového zadání.

- Enumy ve filtrech reprezentuj jako string (ArticleFilter.Type). Specifikace porovnává ArticleEntity.Type.ToString() s textovým filtrem bez převodu vstupu na enum; porovnání ignoruje velikost písmen. ArticleEntity.Type a Article.Type zůstávají ArticleType s HasConversion<string>(); neznámý název typu nenajde shodné články, nevrací validační chybu.

- Výchozí řazení je Id vzestupně. Specifikace obsahuje explicitní whitelist názvů SortBy a typovaných lambda selectorů; články povolují Id, Title, Type, CreatedAt, UpdatedAt. Chybějící, prázdný nebo neznámý SortBy používá Id bez validační chyby; SortDirection se samostatně nevaliduje, pouze desc zapíná sestupné řazení. U jiného primárního sloupce přidej Id jako jednoznačný ThenBy. Nepoužívej reflexi nad libovolným názvem sloupce od klienta.
- AutoMapper konfigurace je sdílená z DI a profilů Application/Mappings, které načítá AddAutoMapper(typeof(EntityMappingProfile)). Používej mapper.Map po načtení entit, nikoli ProjectTo v repository dotazu. Profil obsahuje společnou otevřenou mapu PagedResult<> -> PagedResult<>; jednotlivé mapy entit převádějí Items a stránkovací metadata se zachovají.

- Endpointy a služby článků podle aktuálních podpisů nepřijímají CancellationToken. Obecné read metody repository zachovávají volitelný token, ale služby používají overload bez jeho předání. Chyby vstupu vrací ApplicationResult přes ResultHelper.Validation, bez try/catch ve službě.

- Časové údaje CreatedAt a UpdatedAt nastavují pouze repozitáře (ExtendedBaseRepository pro běžné entity, CreateUserAsync v UserRepository pro registraci přes Identity). DbContext nepřepisuje SaveChanges kvůli časům a neprochází ChangeTracker. Automatické interní změny Identity mimo repository čas UpdatedAt nemění. Samotné ukládání změn zůstává v UnitOfWork a interních mechanismech Identity; repository nemá obecný Commit ani SaveChanges.

- DependencyInjectionExtension rozděluje registrace do RegisterServices, RegisterRepositories, RegisterValidators, RegisterMappings a RegisterHostedServices. Vlastní scoped registrace používej přes TryAddScoped včetně registrace rozhraní DbContextu. Registrace knihoven a hosted služeb používají jejich odpovídající registrační API a zachovávají původní lifetime.

- Automatická kontrola stylu používá vestavěné .NET/Roslyn analyzátory bez StyleCop balíčku. Pravidla jsou v kořenovém .editorconfig; Directory.Build.props zapíná nejnovější úroveň analyzátorů v editoru i při buildu. Vybraná pravidla z číslovaného seznamu: 8, 9, 10, 11, 12, 15, 17, 18, 21, 23, 24, 29, 30, 33, 36, 38, 39, 40. Kontrolují umístění using, závorky a odsazení, file-scoped namespace, switch/throw expressions, zbytečné this, ?? a ?., kolekční výrazy, přístupnost, příponu Async, nepoužívané using/parametry, uvolňování IDisposable a parametry argumentových výjimek. Nepoužívané parametry jsou suggestion, ostatní explicitně vybrané diagnostiky warning; warnings se nepřevádějí na errors. - VS Code má v .vscode/settings.json zapnutý fullSolution pro dotnet.backgroundAnalysis.analyzerDiagnosticsScope a compilerDiagnosticsScope. V multi-root workspace nastav stejné hodnoty také v jeho sekci settings; samotné MSBuild vlastnosti neurčují rozsah živé analýzy editoru.

- .editorconfig preferuje primary konstruktory přes csharp_style_prefer_primary_constructors=true a hlásí možnosti převodu jako warning IDE0290.

- NSwag klient se generuje pouze ručně z běžícího API příkazem dotnet msbuild PublicSafetyHub.NSwagClient/PublicSafetyHub.NSwagClient.csproj -t:GenerateApiClient. Běžný build klienta ani solution generování nespouští. Target v PublicSafetyHub.NSwagClient/Directory.Build.targets používá OpenApiUrl (výchozí https://localhost:7102/openapi/v1.json), kterou lze přepsat parametrem -p:OpenApiUrl=... . NSwag.MSBuild 14.7.1 s runtime Net100 generuje Generated/PublicSafetyHubClient.g.cs podle nswag.json. Klienti AuthClient/IAuthClient a ArticlesClient/IArticlesClient i DTO jsou v PublicSafetyHub.NSwagClient.V1; používají předaný HttpClient s BaseAddress a System.Text.Json. Časy jsou DateTime. Klient nemá ProjectReference na Host. Build-time export OpenAPI, balíček Microsoft.Extensions.ApiDescription.Server a režim GetDocument.Insider jsou odstraněné. Číselná OpenAPI schémata se normalizují na integer/number pro korektní NSwag DTO bez změny runtime JSON deserializace; OperationId má tvar Controller_Action. Generovaný kód neupravuj ručně.

- Úpravy OpenAPI pro NSwag jsou oddělené transformery v Host/BuilderExtensions: NumericSchemaTransformer upravuje číselná schémata, OperationIdTransformer nastavuje Controller_Action. OpenApiServiceCollectionExtension je pouze registruje přes AddSchemaTransformer a AddOperationTransformer.

- Ruční generování NSwag klienta spouští také PublicSafetyHub.NSwagClient/GenerateClient.ps1. Skript obnoví NuGet závislosti a zavolá GenerateApiClient; parametr OpenApiUrl přepisuje adresu běžícího API.
